# NUMA-aware GPU selection fork

This fork automatically detects, selects, rejects, and balances assignments across GPUs
in a multi-GPU system. `NUMA-aware` is the default release branch. It includes
GPU-local CPU affinity, preferred local RAM, CPU-aware GPU selection, AMD/Mesa and
Intel VA-API support, experimental NVIDIA CUDA/NVENC support, and shared application sessions.

Use these matching images:

- Wolf in Docker or Compose: `ghcr.io/greaper88/wolf:latest`
- Wolf UI in its `config.toml` app runner: `ghcr.io/greaper88/wolf-ui:latest`

**Existing installations must update both image references** when switching from a
development channel. Fresh configurations generated by `wolf:latest` already select
`wolf-ui:latest`; existing configurations keep their saved image. Wolf UI is launched
by Wolf, so `docker compose pull` alone does not update its image.

After updating the saved references, pull both images and recreate Wolf:

```bash
docker pull ghcr.io/greaper88/wolf:latest
docker pull ghcr.io/greaper88/wolf-ui:latest
docker compose up -d wolf
```

Stop and relaunch existing Wolf-UI sessions to use the updated UI image.
See the [GPU selection guide](docs/modules/user/pages/gpu-auto-selection.adoc) for configuration.

| Channel | Branch | Wolf image | Wolf-UI image |
| --- | --- | --- | --- |
| Primary | `NUMA-aware` | `ghcr.io/greaper88/wolf:latest` | `ghcr.io/greaper88/wolf-ui:latest` |
| Development | `dev-NUMA-aware` | `ghcr.io/greaper88/wolf:numa-aware-dev` | `ghcr.io/greaper88/wolf-ui:gpu-selection-dev` |
| Upstream baseline | `stable` | — | — |

The other branches are retained under their existing names and documented as stale
in the [branch status guide](docs/modules/user/pages/branch-status.adoc). Use the
primary or NUMA development channel for future fork updates. `stable` remains the
upstream baseline and is not the fork's release channel.

Optional selection preferences: `WOLF_GPU_PREFER_RAY_TRACING=FALSE` and
`WOLF_GPU_ALLOW_LAST_RESORT=TRUE`. Enable RT preference to favor verified RT
cards; disable last-resort use to exclude fallback cards. Individual GPUs can
be excluded with the existing `WOLF_GPU_BLACKLIST` Compose setting.

`WOLF_NUMA_MODE=auto` is the default. Compatible multi-node hosts keep each
session's CPUs local to its selected GPU and prefer local RAM with permitted
remote fallback. Comparable GPUs can be ranked by their local CPU load. Ordinary
single-node systems skip NUMA placement and CPU-load sampling. Use `on` to request
placement explicitly or `off` for ordinary scheduling.

Allow memory-policy syscalls in Wolf's container, for example with `cap_add: [SYS_NICE]`
in its saved Compose configuration. Existing operator resource limits still apply;
CPU affinity does not spill into the other node. See the
[NUMA configuration guide](docs/modules/user/pages/numa-awareness.adoc) for setup,
permissions and placement limits.

## Limitations

- Automatic GPU selection requires startup-verified VA-API or NVENC hardware encoding.
  AMD/Mesa and Intel use VA-API; NVIDIA uses device-bound CUDA/NVENC.
- NVIDIA support remains experimental. Hardware validation includes GTX 1080 and
  Quadro RTX 4000 cards. Wolf's container needs NVIDIA library/device injection
  (for example, native CDI with the NVIDIA Container Toolkit) and DRM modesetting
  enabled. Version-matched 64-bit and 32-bit app driver volumes are created and
  checked at startup. See the [driver configuration](docs/modules/user/pages/configuration.adoc).
- Running and paused apps remain pinned to their assigned GPU.
  Load balancing applies when assigning new sessions.
- Multi-user lobbies use their app's pinned GPU. Compatible viewers share an
  encoder; different stream settings require a separately admitted encoder.
- Virtual GPU slicing and management are not implemented.

Wolf is a streaming server for [Moonlight](https://moonlight-stream.org/) that allows you to share a single server with
multiple remote clients in order to play videogames!

![Wolf basic flow chart](https://github.com/games-on-whales/wolf/blob/stable/docs/modules/ROOT/images/wolf-introduction.svg?raw=true)

It's made from the ground up with the following primary goals:

- Allow multiple users to stream different content by sharing a single remote host hardware
- On demand creation of virtual desktops with full support for any resolution/FPS without the need for a monitor or a
  dummy plug.
- Allow multiple GPUs to be used simultaneously for different jobs
    - Example: stream encoding on iGPU whilst gaming on GPU
- Provide low latency video and audio stream with full support for gamepads
- Linux and Docker first: run your games with low privileges in containers (based
  on [Games On Whales](https://github.com/games-on-whales/gow))
- Mostly hackable, just edit the config file to modify encoding pipelines, GPU settings or Docker/Podman low level
  details

It's a specific tool for a specific need, are you looking for a general purpose streaming solution?
Try out [Sunshine](https://github.com/LizardByte/Sunshine)!

Want to give it a spin? [Checkout our docs](https://games-on-whales.github.io/wolf/stable/)!
