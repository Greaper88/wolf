== Problem and repair

The local Fedora Plasma image received the correct, isolated GTX 1080 and NVIDIA
driver libraries through native CDI. However, CDI preserved the Ubuntu host's
`/usr/lib/x86_64-linux-gnu` library paths. GOW's Fedora NVIDIA startup script
checked only `/usr/lib64/libnvidia-allocator.so.1`, skipped its toolkit setup, and
left Fedora's `/usr/lib64/gbm` without the NVIDIA GBM backend. KWin consequently
used QPainter software compositing, and Xwayland failed to initialize glamor.

Both GOW base startup scripts now resolve `libnvidia-allocator.so.1` through
`ldconfig -p`, detect the actual injected file, and link it into the image's own
GBM backend directory. The existing driver-volume path and JSON setup are kept.
No driver or host desktop configuration is changed by this repair.

The source is isolated in the detached `gow-nvidia-gbm-dev` worktree, based on GOW
commit `a65d67acf287c6b1dce83aa322d9b01958abdf0a`. The original GOW checkout and
the original `gow/plasma:local` image remain unchanged.

Changed GOW files:

* `images/base/build/overlay/etc/cont-init.d/30-nvidia.sh`
* `images/base/build-fedora/overlay/etc/cont-init.d/30-nvidia.sh`

== Validation

Before the repair, a GBM/EGL diagnostic running as the desktop user selected the
generic `drm` backend and failed EGL initialization. Supplying the injected GBM
directory to that diagnostic process alone selected `nvidia` and initialized
NVIDIA EGL successfully, confirming the path mismatch.

A separate Wolf-created Plasma lobby on GPU1 (`0000:07:00.0`, `renderD129`) then
validated the repaired image without changing the maintainer's active desktop:

* Default GBM selected `nvidia` and initialized NVIDIA EGL without an override.
* KWin reported OpenGL compositing, NVIDIA EGL, and the GTX 1080 renderer.
* Xwayland `glxinfo -B` reported direct rendering on the GTX 1080, OpenGL 4.6.
* Native CDI exposed only the assigned GPU UUID and its DRM/device nodes.
* A fresh diagnostic client joined the private lobby and received 121 HEVC frame
  indices over approximately four seconds. FFprobe decoded 120 frames at
  640x360; the decoded image visibly showed the Plasma desktop. The stream used
  CUDA producer buffers and the GPU1 NVENC encoder.
* The diagnostic lobby, client and container were removed; the real user desktop
  and launcher remained running.
* Both edited shell scripts passed `bash -n`; the GOW patch passed
  `git diff --check`. Ubuntu-image runtime validation was not performed here.

An earlier capture attempt reused a stopped UDP receiver and received no packets.
Recreating only the diagnostic client fixed that test setup. A capture taken
before the lobby join showed the launcher producer and was not counted as the
Plasma validation. The final saved capture is the successful joined-lobby test.

The minimal test runner omitted Flatpak/FUSE permissions. Flatpak launch behavior
was outside this graphics check. There was one startup framebuffer warning, but
the compositor stayed on NVIDIA and the decoded desktop stream worked.
