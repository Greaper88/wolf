== Problem and evidence

Wolf-UI intermittently failed its five-second `/api/v1/sessions` request. Its
footer disappeared on the failure and returned on a successful poll. Direct
requests from both UI containers succeeded, and the socket inode matched the
server. The endpoint remained valid in the modified stack.

A short EventPipe trace from the running UI captured `SocketException (32):
Broken pipe`, wrapped by `IOException` and `HttpRequestException`. A second trace
showed the same HTTP connection ID used for a completed lobby request and then
reused for a session request before the client noticed that Wolf had closed it.
Decompiling the running UI assembly confirmed that its client matched the source.

Ordinary Wolf API sockets process one request. Their responses supplied a content
length but no explicit `Connection: close`. That allowed the UI's HTTP connection
pool to race the server's socket closure. Standalone and headless Godot probes
without the full live UI request pattern did not reproduce the failure; those
successful probes alone were not treated as proof that the live issue was fixed.

== Changes

Wolf now adds `Connection: close` unless the response already specifies a
connection header. This covers JSON, icons and errors, while retaining the
explicit `Connection: keep-alive` on SSE event subscriptions. Socket write
ordering and download streaming are unchanged.

The companion UI preserves the last GPU footer readings on failed polls, as
requested by the maintainer, and logs the underlying exception type and message
alongside the outer request error. This does not add blanket retries, including
to requests that could create or stop an app.
