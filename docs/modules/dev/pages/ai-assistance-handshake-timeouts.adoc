= Bound unfinished GPU admissions and protect newer reconnects

AI-Agent: ChatGPT Codex

AI-Model-Version: GPT-6 family; exact serving version and reasoning setting unavailable

AI-Inference-Date: 2026-10-17 12:34:30 UTC

== Problem

HTTPS launch/resume reserves encoder demand before RTSP negotiation starts.
A client that abandons its connection before ANNOUNCE never creates the RTP
waiter, so the existing RTP timeout cannot release that pending admission.
Three interrupted launchers can leave three idle GPUs marked as starting
indefinitely. Repeated resume calls reused that admission without clearing it.

== Change

Unclaimed encoder admissions now have a 30-second monotonic deadline.
The next admission/encoder-start operation expires overdue handshakes back to
retained state. The app and its GPU assignment remain intact. Repeated calls
within an admitted handshake do not extend its original deadline. A late
encoder start must pass admission again. Actual encoder startup and running
encoders are exempt; cancelled teardown holds its capacity until its owners
exit. Same-reservation handoffs also have a bounded unclaimed interval.

The existing RTP video timeout now checks the current connection credentials
under the same transition lock used by HTTPS resume. An old waiter cannot
pause a newer connection reusing that client ID, and a duplicate waiter cannot
pause a stream whose video worker is already running. Credentials are never
included in the diagnostic message.

== Historical diagnosis and limits

Saved logs separately showed repeated RTSP ambiguous legacy-session failures
for clients sharing an address after successful GPU admission. The timeout
prevents abandoned handshakes from indefinitely blocking later GPU admission;
it does not provide the missing client identity or resolve that RTSP ambiguity.
No utilization thresholds, codec checks, GPU isolation or app pinning rules
were relaxed. Historical UI crashes following server shutdown do not establish
a GPU driver fault. The reboot also restored an older Wolf container after a
Docker duplicate-name registration conflict; that is a separate deployment
issue, not a selector-policy change.

at the deadline, retries that cannot extend it, preserved pins, late starts,
new admissions protected from old deadlines, actual encoder startup/running
streams, and cancelled teardown capacity. Independent session tests cover
stale/current RTP identities, live workers and removed/reused session IDs.
The full Wolf server and test executable builds passed. All five standalone
GPU suites passed, including 123 pipeline/lifecycle checks. The shared-video
suite passed 119 assertions in seven test cases with hardware-only checks

used private runtime directories and no live Docker or GPU workloads. Existing
compiler deprecation warnings were unrelated to this change. Formatting and

The already-running-worker timeout check covers an established worker; a
same-generation duplicate waiter racing a simultaneous worker start remains
an existing boundary case outside the admission-lease repair.
